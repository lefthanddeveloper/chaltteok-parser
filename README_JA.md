# chaltteok-parser

[English](README.md) | [한국어](README_KO.md) | **日本語**

曖昧な依頼を勝手に解釈しない Claude Code スキルです。

> **개떡같이 말해도 찰떡같이 알아듣는다**
> *「雑に言われても、きちんと汲み取る」* — 韓国のことわざ

このことわざは普通、察しの良さを褒める言葉として使われます。けれどこのスキルは、
もっと素っ気ない立場を取ります。雑な依頼を正しく理解する確実な方法は、
**うまく当てることではなく、訊くこと**だ、と。

---

## 何をするのか

依頼が二通りに読めるとき、Claude はたいてい「ありそうな方」を選んで作業を進めます。
その推測が当たっていれば一往復ぶん得をしますが、外れていれば、
**作業が終わってから**それを知ることになります。

このスキルが禁じるのはただ一つ、**黙って解釈を選ぶこと**です。自分で調べて確かめる、
利用者に訊く、選んだ解釈を明示して進む — このいずれかは必ず行います。

| 手 | 使う場面 |
|---|---|
| **自力で解決** — コード・会話・設定から答えを探す | 答えがすでにどこかに存在するとき |
| **質問** — 着手前に分岐を利用者に示す | 解釈によって作業が変わり、**外したときの代償が大きい**とき |
| **明示** — 選んだ解釈を一行で述べて進む | 解釈は分かれるが、外しても簡単に戻せるとき |

三つのうち二つは利用者の時間を使いません。そこが要点です。曖昧さの大半はスキル自身が
閉じ、本当に重要な分岐にだけ利用者の注意を使います。

## 例

> **利用者:** セッショントークンの有効期限を30日に延ばして。

十分に明確です。数値も対象も示されています。ところがコードを読むと、依頼には
書かれていない事実が出てきます。`logout()` はトークンを `revoked_tokens`
テーブルに記録しますが、`verifyToken()` はそのテーブルを**一度も参照しません**。
つまりログアウトは実際には何も無効化していない、ということです。有効期限が
2時間なら危険な窓は2時間ですが、30日にすると、漏れたトークンが**1か月ものあいだ
有効なまま、止める手段がありません**。

黙って変更することも、拒むこともせず、スキルはその代償を先に示します:

> 現状、ログアウトは実際にはトークンを無効化していません — `verifyToken()` が
> `revoked_tokens` を参照していないためです。2時間なら小さな窓ですが、30日に
> すると漏れたトークンが1か月有効なまま、回収できません。
>
> - **このまま30日にする（推奨）** — リスクを受け入れる。1行の変更とテスト1件の修正。
> - **リフレッシュトークンを導入** — アクセストークンは2時間、更新用トークンを30日に。
>   より安全ですが、モバイルクライアントが認証 API を固定参照しているため、
>   リリース順序の調整が必要です。
> - **失効処理を先に直す** — `verifyToken()` が失効リストを確認するようにする。

元の依頼は**推奨の選択肢としてそのまま残っています**。変わったのは、代償が見える
状態で選べるようになったという点だけです。

## 黙っているとき

この種のスキルが失敗する典型は**質問のしすぎ**です。そのため内容のおよそ半分は
「訊くべきでないとき」に割かれています。以下の場合、スキルは前に出ません。

- 答えがリポジトリにある → 自分で読みに行きます
- どちらに読んでも作業が同じ → そのまま進めます
- すでに答えが出ている（会話中、あるいは `CLAUDE.md` に） → 訊き直しません
- 慣例的な既定値があり、別を望む気配もない → それに従います
- 外しても簡単に戻せる → 明示して進みます
- 「もう訊かないで」、あるいは判断を委ねられた（「任せる」は立派な回答です）

また、範囲を絞ることを口実に**動かないものを渡したりもしません**。「lint スクリプトを
追加して」が意味するのは*動く* lint スクリプトであって、実行した瞬間に落ちる一行では
ありません。

## インストール

**プラグインとして（推奨）:**

```
/plugin marketplace add lefthanddeveloper/chaltteok-parser
/plugin install chaltteok-parser@chaltteok
```

**スキルファイルを直接置く場合:**

```bash
git clone https://github.com/lefthanddeveloper/chaltteok-parser.git /tmp/chaltteok
cp -r /tmp/chaltteok/skills/chaltteok-parser ~/.claude/skills/
```

特定のプロジェクトだけで使うなら、`~/.claude/skills/` ではなくそのプロジェクトの
`.claude/skills/` に置いてください。

インストール後は呼び出す必要はありません。依頼が曖昧に見えたとき、自動的に働きます。

## 構成

```
skills/chaltteok-parser/
├── SKILL.md                          中核となる手順
└── references/
    ├── ambiguity-patterns.md         曖昧さの11類型
    └── worked-examples.md            例7件、それぞれ失敗例と並記
```

スキルが起動すると `SKILL.md` が読み込まれます。参照ファイルは、必要だと判断された
ときにだけ追加で読み込まれます。
